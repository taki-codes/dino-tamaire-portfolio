# 設計と検証の読みどころ

モバイルゲームの物理更新、CPU、同時操作、描画の分担を確認するための案内です。実機映像の代わりにシミュレーションを提示するものではありません。

## コードを読む順番

1. [App.tsx](../App.tsx): モード選択と画面遷移。
2. [useGameLoop.ts](../src/game/useGameLoop.ts): フレーム更新と復帰時の時間差の制御。
3. [physics.ts](../src/game/physics.ts) / [cpu.ts](../src/game/cpu.ts): 弾道とCPUの判断。
4. [robot.ts](../src/game/robot.ts) / [シミュレーション](../tools/robot-sim-test.ts): 攻撃・ガード・カウンター・HP・勝敗の対応。
5. [src/render](../src/render) / [src/screens](../src/screens): ゲーム状態を描画と操作へ接続する部分。

## 設計上の選択

同じ端末の上下で対戦する構成なので、ネットワーク同期はありません。ゲーム状態をフレームごとに更新する処理と、Skiaによる描画を分け、ルールごとの差をゲーム層で扱います。設定はメモリ内に保持するため、再起動後の復元は今後の課題です。

## 再現できる確認

```sh
npm ci
npm run typecheck
npm run test:robot
```

2026年11月8〜9日、Windows / Node.js 24.22.1で型チェックと既存シミュレーションの25アサーションが成功しました。乱数のseedはテスト実行プロセスだけで固定し、製品の乱数処理は変更していません。端末なしでロジックを確認できます。

シミュレーションはロボットモードの一部を対象とします。全モードの物理精度、マルチタッチ、描画fps、音・振動、ネイティブビルドの確認は含みません。面接でデモする際は、実機で「CPU戦 → 同時操作 → ロボットのガード・カウンター」を確認し、実際の端末・OSを併記してください。
